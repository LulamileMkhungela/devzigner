# The docs, and where each one is applied

Thirteen documents describe how ProdOps-built products are planned, shaped and
shipped. They are kept here in the repository — not only quoted on a page — and
each one is applied by a specific surface, listed below.

They were written upstream under the MIT licence and are reproduced here with the
product names of this project (ProdOps, Standards, Starter, Agents canon). The
workflow they describe is the workflow the app enforces.

| Document | What it decides | Where it is applied |
| --- | --- | --- |
| [agents.md](agents.md) | The two contexts (the app vs. the product), the ten commands, and the order they run in | `src/engine` and `src/views` — the five stages; `.agents/commands/prodops/` — the same ten commands on disk |
| [getting-started.md](getting-started.md) | Install, then the first run | `#prodops-install` on all eight tool pages; `npm run kit` |
| [product-planning.md](product-planning.md) | How a brief becomes a locked scope | Product stage (`/product-vision`, `/product-roadmap`) |
| [requirements.md](requirements.md) | The shape of a requirement and its acceptance check | Sections stage (`/shape-section`), `shape.md` + `plan.md` |
| [design-section.md](design-section.md) | How one section is designed, screen by screen | Sections stage (`/design-screen`, `/screenshot-design`) |
| [export.md](export.md) | What the handoff package contains | Export stage (`/export-product`), `product-plan/` |
| [codebase-implementation.md](codebase-implementation.md) | How the exported artefacts are wired into a codebase | `src/export/frameworks`, `instructions/incremental` |
| [usage.md](usage.md) | The day-to-day loop | `src/views/WikiPage.tsx`, `src/components/NextStepGuide.tsx` |

| [README-upstream.md](README-upstream.md) | The project's own summary | `README.md` at the repository root |

| [components.json](components.json) | The component conventions (new-york, lucide, DM Sans) | `src/export/standards.ts`, `src/styles/app.css` |

## From document to running command

```bash
npm run kit   # rewrites .agents/ and standards/ from the vendored instructions
npm run check # proves the pages, the package, the walkthrough and the build
```

The eight tools' installation sections copy from `.agents/skills/` and
`template/starter/`. Those paths exist because `npm run kit` writes them, and
`npm run site-check` fails if any page promises a path this repository does not
have.

## The five stages and the ten commands

```
Product      /product-vision  /product-roadmap
Data Shape   /data-shape
Design       /design-tokens   /design-shell
Sections     /shape-section   /sample-data  /design-screen  /screenshot-design
Export       /export-product
```

A stage ticks only when it is confirmed — artefacts being complete is not the
same thing. See `AGENTS.md`, and the stage header in the workspace.
